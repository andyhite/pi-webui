PlotRoom design system · v1
Every piece of the interface, what it means, and when it changes.
PlotRoom is a canvas for running coding agents against real work. Tickets, pull requests, reviews and documents are pulled onto a spatial graph; commands are wired to those inputs; sessions are the runs those commands produce; workstreams frame a piece of work. The operator's job is triage, so the whole system exists to answer one question at a glance: what needs me?
HOW TO READ THIS §01–07 are the language: colour, type, glass, the atoms, the node grammar, chrome, panels, voice. §08–09 are the reference: every kind at every size, then measured redlines. §10–15 are behaviour: interaction, keyboard, data, layout and routing, zoom mechanics, window and accessibility. §16–18 are the new states, the assembled screens, and the token table.
RULES OF THE DOCUMENT Every number is exact and measured at 1440 × 900. Odd values (9, 11, 12.5, 158°) are deliberate — do not round them. Every value has a token name in §18. Use those names in the implementation. Dark only. There is no light theme, and no value here has a light-mode counterpart. §16 is newly designed and unreviewed. Everything else derives from decisions already committed.

The frame sits at a lower tint (.075 → .03) and a larger radius (16) than the nodes inside it, so it reads as ground rather than another card. Its band carries identity and the rollup of attention; its footer strip carries counts on the left and money on the right, always in that order.

EDGES Four line languages, no more
All four are 1.4px with a small triangular arrow. Edges live in one layer beneath the nodes and never receive pointer events. Only the route out of the current selection is allowed to be bright; everything else stays at .34 so a dense graph still reads as background structure. Reach for a curve only when a straight line would cross a node.
RELATIONS What connects to what
content → commandsolid. The command depends on that input; if the input moves, the command drifts.
command → sessionproducer dash, violet. One command can produce many sessions; forks fan out downward.
session → contentfine dash. The session read or authored that artifact — provenance, not dependency.
content → contentfine dash. A review on a pull request, a diff from a commit.
workstreamno edge. Containment is the relation; drawing it would double the information.
Direction always reads left to right for dependency and top to bottom for production, which is why forks stack vertically under their command. Drift is the one relation that has a colour rather than a line: the input's edge stays neutral and the dependent node turns amber.

PANEL RULES Shared behaviour across every panel
Titled in sans, sentence case. Panels are the one place a heading is not mono — nodes are titled by their own identity, panels by their function. Header carries scope, not actions. A chip says what the panel is showing; expand and close sit right; a mono shortcut hint sits between them. One metric strip, fixed order. state · turns · elapsed · spend · context. Spend is the only bright value.
Floated, never docked. Panels overlay the canvas at radius 14 with the heaviest shadow in the system; the graph keeps its position underneath. Sections, not tabs. A panel scrolls through labelled sections rather than hiding content behind tabs — triage is comparison. Amber is spent once. In a transcript that budget goes to the question card. Questions are decisions with named options, never open prompts, and exactly one option carries the agent's recommendation. Refusals name the rule, state what was attempted, and say what happened instead — in place, as a line in the node, never as a dialog.
NEVER Out of scope by decision
Exclamation marks, emoji, "Oops", "Great!", or any encouragement. Error dialogs and modal confirmations — state it in place instead. A light theme. Every value here assumes a dark canvas. Imagery, illustration, or photographic backgrounds. A type hue on text, an edge, or a chip fill. Amber on anything that is not asking for a human. Spinners and pulses. A running session moves its numbers. Tabs inside panels; nested workstreams; a fifth header slot.
OPEN Not yet decided
Logo. No mark exists. The chrome lockup is a glass tile holding the attention chip beside the wordmark — a placeholder, not a decision. Fonts. Both faces are Google-hosted. No licensed binaries have been chosen. Empty states. An empty canvas, an empty palette and a workstream with no commands are all unspecified. Multi-select. Selection is defined for one node. Rubber-band selection and bulk actions are not. Keyboard map. ⌘K, ⌥1, ⌥↵ and ↵ appear in the design; the full map is not written down.

10 Interaction Pointer behaviour, selection mechanics, drag. Every visual delta is specified.
HOVER & PRESS Background and border only
node hoverborder alpha .32 → .44, tint gradient top stop .14 → .17. No lift, no scale, no shadow change.
node presstint top stop .11, lip .22 → .12. Reads as pushed into the glass.
control hoverfill .055 → .09, border .09 → .14. Amber primary darkens to #f0973a.
control pressfill .14, lip removed. Never a transform.
row hoverpalette and history rows: fill +.02, title steps one text level brighter.
edge hovernot hoverable. Edges are pointer-events: none at every zoom.
timing90ms in, 90ms out, --pr-ease. Only background-color and border-color transition.
cursorcanvas grab / grabbing while panning · node default (it is a target, not a link) · control pointer · port crosshair · frame band move
at far zoomhover is the only feedback available; a far node is too small for a state word, so hovering brightens the border and shows a 250ms-delayed tooltip carrying the title.
SELECTION One primary, many secondary
clickselects, replacing the selection. Clicking empty canvas clears it.
⇧ clickadds to the selection. The last-clicked node is primary and keeps the full treatment (1.5px edge, halo, ports); secondary members get the 1.5px edge only, no halo, no ports.
⌘ clicktoggles one node in or out without changing primary.
rubber banddrag on empty canvas draws a 1px rgba(230,233,236,.5) rect with rgba(230,233,236,.04) fill, radius 4. Selects on intersect, not containment. ⇧ adds to the existing selection.
double clickzooms to that node at full LOD and centres it. On a frame band, zooms to fit the frame.
bottom barshows the primary node. With a multi-selection it shows n selected and the aggregate: types present, total spend, count needing a human.
active routeonly edges incident to the primary node brighten. A multi-selection does not light up a web of routes.
frame selectclicking a frame's band or background selects the workstream itself, not its children. Selecting the frame does not select its contents.
persistenceselection survives zoom-level changes and panel toggles. It is cleared by a repo-scope change, since the node may no longer be in view.
DRAG, PAN, ZOOM Direct manipulation
drag a nodemoves it. Ghost is the node itself at opacity .85 with shadow raised to the frame step; a 1px dashed rgba(255,255,255,.14) outline marks the origin. Edges re-route live.
drop into framea valid frame lifts its border to rgba(hue,.45) and its tint top stop to .12. Dropping reparents. Dropping on empty canvas removes it from the frame.
invalid dropno red state and no snap-back animation. The node simply does not reparent and stays where it was released — refusals are recorded, not enforced with motion.
drag a portdraws a live edge in the active language from the port to the cursor. Valid targets get the same border lift as a frame; the edge snaps to the target's nearest port within 24px.
drag from palettethe row lifts as a mid node at opacity .85 — you drag the thing itself, not a proxy chip. Dropping places it at the cursor, snapped to grid.
multi dragdragging any selected node moves the whole selection, preserving relative offsets. Grid snap applies to the primary node only.
panspace-drag anywhere, middle-drag anywhere, or two-finger scroll. No inertia — the canvas stops when the gesture stops.
zoom⌘/ctrl + scroll, pinch, or the zoom pill. Anchored on the cursor for scroll and pinch, on the viewport centre for the pill and keyboard.
zoom range15% to 200%, continuous. Clamped, not elastic.
pan boundsthe graph bounding box plus 50% of the viewport in each direction. You can always get the graph off-centre, never lose it.
chrome scalebars, rail, panels, minimap and markers never scale. Only the graph layer transforms.
during gesturehover states are suppressed and tooltips cancelled. Attention signals keep updating — a session finishing mid-pan still turns amber.
minimap dragdragging the viewport rect pans; clicking anywhere in the minimap centres the view there at the current zoom.

DERIVED VALUES Computed, never stored

Every number visible on a node is either a stored field or one of these. If a value cannot be traced to this list, it does not belong on the canvas.
13 Layout & routing Where nodes land, and how edges get between them.
GRID & PLACEMENT 28px grid, snapped on release
grid28px, the same value as the visible dot grid — the dots are the snap targets, not decoration
snapon release, not during drag. The node follows the cursor freely and settles in 160ms.
snap overridehold ⌥ while releasing to place freely
anchorthe node's top-left corner snaps, so nodes of different widths still align on their left edge
collisionnone. Nodes may overlap; the operator's arrangement is never corrected. Overlap is a signal that the graph needs tidying, and hiding it would hide that.
new nodeplaced at the drop point, or — when created by a shortcut — at the first free grid cell to the right of the selection, searching down then right
new sessionappears 140px below its command, forks fanning left to right in creation order. This is the one automatic placement in the product.
auto-layoutoffered, never applied: ⌘⇧L tidies the current selection into columns by family — content left, commands centre, sessions right — and is a single undoable action. Nothing re-lays out on its own.
zoom re-layoutpositions are stored once, in canvas space, and do not change with zoom. Only the rendered node size changes, so at far zoom the gaps look larger — that is correct and intended.
EDGE ROUTING Straight first, one curve if needed
portsfour per node, at the midpoint of each edge of the card. Dependency uses left and right, production uses top and bottom.
port choicethe pair with the shortest straight line, subject to the axis rule above
straightused whenever the segment clears every other node's bounding box by 8px
curvea single cubic bezier with control points pulled along the source and target port normals by 40% of the span. Never two curves, never an orthogonal elbow route.
unavoidableif no route clears, the edge crosses. A crossing is acceptable; a wandering path is not.
arrowhead7×7 triangle, refX 7, at the target end only, inset to the target's border
parallel edgesmultiple edges between the same pair fan out from evenly spaced points along the port edge, 10px apart
crossing framesan edge leaving a frame exits through the nearest frame border and is drawn on the canvas layer, under the frame's band. Frames do not clip their outgoing edges.
at far zoomedges stay 1.4px in screen space, not canvas space — they do not thin out as you zoom away, or the graph structure would disappear before the nodes do
density capabove 200 visible edges, provenance edges (the fine dash) drop out first; dependency and active routes always render
14 Zoom mechanics Thresholds, hysteresis, and exactly what animates across a level change.
THRESHOLDS Two boundaries, both with hysteresis
15% min 45% 80% 200% max far · 150×34
icon · id · signal mid · 268w
+ title, live line full · 340w
+ regions, controls — the only actionable level
hysteresiseach boundary has a ±3% dead band: crossing 45% upward promotes at 46.5%, downward demotes at 43.5%. Without it, a node sitting on a threshold flickers as the trackpad drifts.
per-nodethe level is global, from the canvas scale — not per node. Two nodes are never at different levels at the same time.
forced fullthe one exception: ↵ or double-click on a node below 80% zooms the canvas to 100% rather than rendering that node differently.
pillthe zoom pill shows the true percentage and the level name; the percentage is continuous, the name changes at the thresholds
what animatesthe node's width and radius over 220ms --pr-ease. Content that is entering fades in over the last 120ms; content leaving fades out over the first 100ms.
what does notthe header never cross-fades — glyph, KIND label and signal are present at every level and must stay put. The node's top-left corner is the anchor, so identity does not move as the card grows.
edgesre-route in the same 220ms window, interpolating endpoint positions rather than re-solving mid-flight
reduced motionlevel changes become instant; nothing else about the ladder changes
text scalingtype sizes are fixed per level and do not interpolate. 9.5px mono is never rendered at 7px — it swaps out at the threshold instead.
15 Window & accessibility Resize behaviour, focus order, contrast, and the reduced-motion contract.
WINDOW Desktop only, three breakpoints
design target1440 × 900. Every measurement in this document is at 1:1 on that viewport.
minimum1120 × 700. Below this the window is not supported; PlotRoom is not a phone or tablet product and does not pretend to be.
< 1280 wideonly one side panel may be open. Opening a second closes the first, and the rail button state follows.
< 1180 widethe minimap hides. Offscreen markers stay — orientation matters more than overview at that size.
< 760 tallthe conversation panel drops its metric strip; the numbers move to the panel header as a chip.
on resizezoom is preserved and the canvas centre stays put. The view never re-fits on its own — a resize is not a request to rearrange your graph.
chromebars are fixed at 42px at every size. Items drop from the middle of the top bar outward — spend goes first, then the repo scope, never the attention count.
panelsfixed widths (226 palette, 356 conversation) and never fluid; they gain height, not width
densityone density. There is no compact mode — the mid node already is one.
ACCESSIBILITY Where the design owes something
focus ring2px #e6e9ec outline at 2px offset, on every focusable element. It is deliberately louder than the selection edge, and it is never suppressed.
focus ordertop bar left to right → rail top to bottom → open panels in rail order → canvas → bottom bar. Within the canvas, nodes are ordered by frame, then top-to-bottom, then left-to-right; a frame's children come immediately after it.
canvas a11ythe graph is a listbox: each node is an option carrying its family, kind, state, signal reason and title as an accessible name. Edges are described on the node ("2 inputs, 1 drifted"), not as elements.
announcementsone polite live region reports signal changes ("plan-review needs you: 1 input drifted") and a session finishing. Turn-by-turn output is not announced.
colour alonenever load-bearing. Signal state is carried by dot shape as well as hue; drift and alert always name themselves in words beside the dot. The four type hues are reinforced by the KIND label and the glyph.
contrasttext steps hi through .56 clear 4.5:1 on every glass body. .44 and .34 do not, and are restricted to the live line, units and provenance — never to a value the operator must read to make a decision. Amber on #231404 and the amber text steps both clear 4.5:1.
hit targetscontrols are 26–30px, below the 44px touch guideline. This is a pointer-and-keyboard product; every control also has a shortcut, which is the accessible path.
reduced motionzoom-level changes, node settle and edge re-route become instant. Hover transitions stay — they are 90ms and carry state. Nothing in the product loops or pulses, so there is nothing else to disable.
transparencyunder reduced-transparency, blurs are dropped and every glass body goes fully opaque at its own alpha composited over #101113. Tints and borders are unchanged, so type coding survives.
